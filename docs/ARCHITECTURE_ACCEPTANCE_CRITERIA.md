# Architecture Acceptance Criteria — معايير القبول المعمارية (v1.1)

شروط نجاح قابلة للاختبار. لا يُعتبر التصميم مقبولًا — ولا تُفتح أي دولة (بوابات الإطلاق، قسم 30) — قبل اجتيازها جميعًا. المراجع بين الأقواس تشير إلى أقسام PROJECT-PLAN-v1.1-VERIFIED-CORRECTIONS.md.

## المعايير المالية

1. **لا رصيد سالب:** لا يوجد أي مسار — بما في ذلك التزامن والأعطال — ينتج رصيد مستخدم سالبًا. يُثبت باختبارات Concurrency (قسم 26) وقيود الـ Ledger البنيوية (قسم 12-د).
2. **لا خصم مكرر:** تكرار أي Webhook أو إعادة أي محاولة لا ينتج خصمًا مزدوجًا — Idempotency Key مستقل لكل وحدة فوترة ولكل عملية مالية (قسم 12-ج، 12-د).
3. **إنهاء البث بعد نفاد الرصيد:** عند تعذر حجز الوحدة التالية يُصدر الخادم أمر Disconnect وتنتهي الجلسة خلال المهلة المعتمدة، ولا يقع أي خصم بعد وقت الإنهاء المعتمد (قسم 12-د).
4. **إعادة الاتصال دون خصم مزدوج:** سيناريو reconnecting لا يستهلك وحدات مكررة ولا يفوتر وقت الانقطاع خلافًا للسياسة المعلنة مسبقًا (قسم 12-هـ).
5. **رد الجزء غير المستخدم:** كل مبلغ محجوز غير مستهلك قابل للتحرير أو الاسترداد، ويُثبت ذلك بمطابقة الـ Ledger (قسم 12-د، 12-هـ).
6. **Reconciliation يومي ناجح:** المطابقة اليومية بين قاعدة البيانات وApple وGoogle ومزود الدفع تكتشف أي فرق وتصعّده (قسم 12-ج).
7. **Fail-Safe عند تعطل Redis:** تعطل Redis لا ينتج بثًا مجانيًا غير محدود ولا خصومات خاطئة؛ الجلسات التي يتعذر تأكيد حجوزاتها تتوقف وفق سياسة مهلة قصيرة (قسم 12-د).

## معايير الدفع والامتثال

8. **لا طريقة دفع غير مسموحة في Storefront المستخدم:** لا يُعرض على المستخدم أي خيار دفع غير مسموح في متجره ودولته — تحكم Feature Flags، ويُختبر لكل صف في Payment Compliance Matrix (قسم 12-أ).
9. **فصل مشتريات الويب عن الهاتف:** مشتريات الويب معزولة في الأنظمة والسجلات، ولا تظهر دعوات دفع خارجية في الأماكن غير المسموح بها (قسم 12-ب، النوع C).

## معايير البيانات والخصوصية

10. **لا يعود المحتوى المحذوف بعد استعادة Backup:** استعادة أي نسخة احتياطية أو Disaster Recovery لا تعيد بيانات محذوفة إلى النظام الحي — فحص Tombstones إلزامي بعد كل استعادة (قسم 24-ب).
11. **لا وقت محلي غامض:** جميع السجلات المالية بتوقيت UTC أصلي، ولا يوجد حقل وقت بلا Timezone في المخطط (قسم 19).
12. **فصل وثائق الهوية:** لا تصل وثائق الهوية إلى قاعدة بيانات المستخدمين العامة؛ الأنظمة تتعامل مع Token أو نتيجة تحقق فقط (قسم 6).

## معايير الحماية والإنفاذ

13. **حظر الالتقاط أو اكتشافه حسب قدرات النظام:** FLAG_SECURE فعّال على شاشات Android الحساسة؛ اكتشاف Capture/Recording/Mirroring فعّال على iOS مع الاستجابات المعرفة (تمويه، إيقاف مؤقت، تحذير، إنهاء) — دون ادعاء منع مطلق (قسم 11-أ).
14. **كل قرار حظر دائم له أدلة متعددة وإمكانية استئناف:** لا حظر نهائي بإشارة جهاز واحدة أو بمخرجات NLP وحدها؛ سبب القرار مسجل ومسار Appeals فعال (قسم 15، 16).
15. **لا محتوى جنسي مدفوع أو خدمات جنسية:** لا يسمح النظام — منتجًا وسياسة وتقنية — بمحتوى جنسي مدفوع أو خدمات جنسية؛ تُختبر مسارات الكشف والإنهاء والبلاغ والتجميد (قسم 1، 11، 15).
16. **بلاغ الإساءة المبكر يعمل كاملًا:** إنهاء فوري بطلب المبلّغ، تجميد أرباح الجلسة في pending، إحالة لمراجعة بشرية، دون إدانة تلقائية (قسم 12-هـ).

## إثبات الاجتياز

كل معيار يُثبت باختبار آلي أو إجراء تحقق موثق ضمن حزمة اختبارات القسم 26 (بما فيها اختبارات Concurrency الإلزامية)، وتُسجل النتائج قبل بوابات الإطلاق (قسم 30). لا يوصف أي معيار بأنه مجتاز دون دليل.
